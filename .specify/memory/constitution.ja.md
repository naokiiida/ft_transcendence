# ft_transcendence 憲法

## 基本原則

### I. Fresh優先モノリシックアーキテクチャ

アプリケーションはDeno Freshを使用した単一のデプロイ可能なユニットとして構築しなければならない (MUST)。

- **単一コードベース**: すべてのアプリケーションコード (ルート、アイランド、API、ゲームロジック) は
  1つのFreshプロジェクト内に存在しなければならない (MUST); マイクロサービスは禁止
- **アイランドアーキテクチャ**: インタラクティブなコンポーネントは選択的ハイドレーションのために
  Fresh Islandsを使用しなければならない (MUST); フルページのクライアントサイドハイドレーションは禁止
- **サーバーサイドレンダリング**: すべてのページは最初にサーバーでレンダリングしなければならない (MUST)
  (SSRモジュール = 1pt); WebSocketエンドポイントを除き、クライアントのみのルートは禁止
- **ファイルベースルーティング**: ルートはFreshの規約 (`routes/`, `islands/`) に従わなければならない (MUST);
  カスタムルーティング抽象化は禁止

**根拠**: モノリシックなFreshアプリはデプロイの複雑さを軽減し、サービス間通信の
オーバーヘッドを排除し、4〜5人のチームがより速く反復できるようにする。
Freshのアイランドアーキテクチャは複雑さなしにSPAのようなインタラクティビティを提供する。

### II. 型安全性第一

Denoのネイティブ TypeScript は厳格な設定とランタイム検証で活用しなければならない (MUST)。

- **厳格モード**: `deno.json` に `"strict": true`; 暗黙の `any` は禁止
- **`any` 型禁止**: `any` の使用は禁止; 代わりに型ガード付きの `unknown` または
  明示的なジェネリクスを使用しなければならない (MUST)
- **ランタイム検証**: すべての外部入力 (フォームデータ、WebSocketメッセージ、URLパラメータ) は
  処理前にZodスキーマを使用して検証しなければならない (MUST)
- **共有型**: ゲーム状態、ユーザーモデル、APIコントラクトは
  サーバーとクライアントの両方のコードからインポートされる `shared/` ディレクトリに定義しなければならない (MUST)

**根拠**: DenoはTypeScriptをトランスパイルなしでネイティブに実行する;
厳格な型付けは本番環境ではなく開発時にエラーをキャッチする。

### III. デフォルトでセキュア

セキュリティはすべてのレイヤーに組み込まなければならない (MUST); 42評価では脆弱性がテストされる。

- **SQLインジェクション防止**: すべてのデータベースクエリは
  パラメータ化されたステートメントで `db.prepare()` を使用しなければならない (MUST); SQLでの生の文字列補間は禁止
  gitフックとClaude Codeフックで強制しなければならない (MUST)
- **XSS保護**: Preactの自動エスケープに依存しなければならない (MUST);
  明示的なセキュリティレビューなしの `dangerouslySetInnerHTML` は禁止
- **CSRF保護**: Freshミドルウェアはすべての
  状態変更リクエスト (POST、PUT、DELETE) でCSRFトークンを検証しなければならない (MUST)
- **認証**: ログインには42 API経由のOAuth 2.0; セッショントークンは
  HTTP-onlyセキュアCookieに保存
- **パスワードハッシュ**: ローカルパスワード (ある場合) はコストファクター10以上のbcryptを
  使用しなければならない (MUST)
- **入力検証**: Zodスキーマはクライアント (UX) と
  サーバー (セキュリティ) の両側ですべてのユーザー入力を検証しなければならない (MUST)
- **HTTPSのみ**: TraefikがTLSを終端しなければならない (MUST); すべてのHTTPトラフィックはHTTPSにリダイレクト

**根拠**: 42プロジェクトはセキュリティを要求する; セキュリティチェックに失敗するとプロジェクトに失敗する。
多層防御は単一障害点を防ぐ。

### IV. リアルタイムゲームアーキテクチャ

ゲーム状態はサーバーで権威を持ち、レスポンシブ性のためにクライアント側予測を行わなければならない (MUST)。

- **サーバー権威**: ゲーム物理とスコアリングはサーバー側で計算しなければならない (MUST);
  クライアントは入力を送信し、サーバーは状態をブロードキャスト
- **WebSocketプロトコル**: ゲームとチャットはクライアントごとに単一のWebSocket接続を共有しなければならない (MUST);
  メッセージタイプはJSONペイロードの `type` フィールドで区別
- **再接続処理**: クライアントは切断時に自動的に再接続しなければならない (MUST);
  サーバーは再参加を可能にするために30秒間ゲーム状態を維持しなければならない (MUST)
- **ティックレート**: サーバーはPongで毎秒30回以上ゲーム状態をブロードキャストしなければならない (MUST);
  クライアントは更新間を補間してスムーズなレンダリングを実現

**根拠**: サーバー権威のゲームロジックは不正を防ぎ、
公平なプレイを保証する—トーナメントの整合性に不可欠。

### V. 監視可能な運用

システムの健全性はPrometheusメトリクスとGrafanaダッシュボードを通じて可視化しなければならない (MUST)。

- **メトリクスエンドポイント**: FreshはPrometheus形式で `/metrics` を公開しなければならない (MUST);
  アクティブなゲーム、接続ユーザー、試合完了のカスタムメトリクス
- **Grafanaダッシュボード**: 事前設定されたダッシュボードはシステムの健全性、
  ゲーム統計、ユーザーアクティビティを表示しなければならない (MUST)
- **構造化ログ**: すべてのログはリクエスト相関IDを含むJSON形式でなければならない (MUST)
- **ヘルスチェック**: `/health` エンドポイントはDockerのサービスステータスを返さなければならない (MUST)

**根拠**: Prometheus + Grafanaモジュール (2pts) とAnalytics Dashboardモジュール (2pts) は
監視可能なインフラストラクチャを必要とする; これは本番環境でのデバッグにも役立つ。

### VI. シンプルさとYAGNI

機能は現在の要件を解決しなければならない (MUST); 投機的な抽象化は禁止。

- **シンプルに始める**: 機能する最もシンプルな解決策を実装する;
  複雑さが証明された場合にリファクタリング
- **早期の抽象化禁止**: 3つの具体的なユースケースが必要になるまで、
  ファクトリー、リポジトリ、プラグインを作成しない
- **デッドコードの削除**: 未使用のコードは即座に削除しなければならない (MUST);
  コミットされたファイルでのコメントアウトされたコードは禁止
- **依存関係の最小化**: すべての外部依存関係はその採用を正当化しなければならない (MUST);
  サードパーティパッケージよりもDeno stdlibとFresh組み込みを優先

**根拠**: 42プロジェクトの締め切りは集中的な開発を要求する;
過剰なエンジニアリングは時間を浪費しメンテナンスの負担を生む。

## 技術スタック

### ドメインとデプロイ

- **ドメイン**: `pong.taiida.com`

- **デプロイ**: [Fresh Dockerドキュメント](https://fresh.deno.dev/docs/deployment/docker)に従ったDockerマルチステージビルド

### ランタイムとフレームワーク

| レイヤー | 技術 | バージョン | 根拠 |
|-------|------------|---------|-----------|
| ランタイム | Deno | ≥1.40 | ネイティブTypeScript、デフォルトでセキュア、組み込みツール |
| フレームワーク | Fresh | ≥1.6 | SSR + Islands、ファイルベースルーティング、Preact統合 |
| UIライブラリ | Preact | ≥10.0 | 軽量なReact代替、自動エスケープXSS |
| CSSフレームワーク | DaisyUI + Tailwind | 最新 | コンポーネントライブラリ、[Fresh DaisyUIドキュメント](https://fresh.deno.dev/docs/examples/daisyui)に従う |
| データベース | SQLite (WALモード) | 最新 | シンプル、ファイルベース、同時読み取り用WAL |
| リバースプロキシ | Traefik | ≥3.0 | HTTPS終端、自動TLS、Docker統合 |

### SQLite設定

```typescript
// lib/db.ts - 接続時にWALモードを有効にしなければならない (MUST)
const db = new Database("data/pong.db");
db.exec("PRAGMA journal_mode = WAL");
db.exec("PRAGMA foreign_keys = ON");
db.exec("PRAGMA busy_timeout = 5000");
```

- **WALモード**: 書き込み中の同時読み取りを有効にする; WebSocket接続に必須
- **ファイル場所**: `data/pong.db` (永続化のためのDockerボリューム)
- **プリペアドステートメント**: すべてのクエリは `db.prepare()` を使用しなければならない (MUST)、文字列補間は禁止

## 開発ワークフロー

### ブランチ戦略

- `main`: 本番準備完了; 保護; PRの承認が必要
- `develop`: 統合ブランチ
- `feature/<name>`: 個別の機能
- `fix/<name>`: バグ修正

### コミット標準

- **フォーマット**: `<type>(<scope>): <description>` (Conventional Commits)
- **タイプ**: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
- **スコープ**: `game`, `auth`, `user`, `chat`, `infra`, `shared`

### コードレビュー要件

- すべての変更は少なくとも1人のチームメンバーによるレビューが必要 (MUST)
- レビューは以下を確認しなければならない (MUST):
  - 生のSQLなし (`db.prepare()` のみ)
  - すべての入力でZod検証
  - `any` 型なし
  - 憲法の原則に従っている
- 重要な変更では自己マージ禁止

### 完了の定義

機能は以下の条件を満たしたときに完了:
1. TypeScriptエラーなし (`deno check`)
2. Deno lint/fmtパス (`deno lint && deno fmt --check`)
3. コードレビュー承認
4. `docker compose up` が動作
5. Chromeで手動テスト (42要件)

## コンテナ設定

### Docker Composeサービス

```yaml
services:
  fresh:        # メインアプリケーション (Deno + Fresh) - pong.taiida.com
  traefik:      # リバースプロキシ + TLS終端
  prometheus:   # メトリクス収集
  grafana:      # ダッシュボード + 分析

volumes:
  sqlite_data:  # 永続SQLiteデータベース (data/pong.db)
```

### Dockerfile (マルチステージビルド)

[Fresh Dockerデプロイドキュメント](https://fresh.deno.dev/docs/deployment/docker)に従う:

```dockerfile
# ステージ1: ビルド
FROM denoland/deno:2.1.4 AS builder
WORKDIR /app
COPY . .
RUN deno task build

# ステージ2: 実行
FROM denoland/deno:2.1.4
WORKDIR /app
COPY --from=builder /app .
EXPOSE 8000
CMD ["run", "-A", "main.ts"]
```

### Traefik設定

```yaml
# docker-compose.ymlのfreshサービスのラベル
labels:
  - "traefik.enable=true"
  - "traefik.http.routers.pong.rule=Host(`pong.taiida.com`)"
  - "traefik.http.routers.pong.entrypoints=websecure"
  - "traefik.http.routers.pong.tls=true"
  - "traefik.http.services.pong.loadbalancer.server.port=8000"
```

### 単一コマンド起動

開発環境は以下で起動しなければならない (MUST):
```bash
docker compose up
```

## ガバナンス

### 憲法の権威

この憲法は他のすべての開発慣行に優先する。
競合が発生した場合、このドキュメントが優先される。

### 改正手続き

1. **提案**: チームメンバーはPR経由で改正を提案できる
2. **議論**: 改正は24時間以上議論しなければならない (MUST)
3. **承認**: アクティブなチームメンバーの50%以上の承認が必要
4. **移行**: 破壊的な改正には移行計画を含めなければならない (MUST)

### バージョニングポリシー

- **MAJOR** (X.0.0): アーキテクチャ変更、原則の削除
- **MINOR** (x.Y.0): 新しい原則、セクション、または拡張
- **PATCH** (x.y.Z): 明確化、タイプミス修正

### 原則違反

- **ソフト違反**: コードレビューで文書化; 迅速に修正
- **ハード違反** (セキュリティ、SQLインジェクション): マージをブロック; 即座の修正が必要
